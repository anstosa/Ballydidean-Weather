`config/rust-contract-roots.json` lists the permitted roots and explicit mapping metadata. The rain collection API projection checks for nonnegative JavaScript safe integers and canonical UTC strings. The rain adjustment projection uses a bounded integer model lead and JSON number fields. The generated declarations record the reviewed mappings without replacing application validation or claiming Rust serialization parity.

Using the repository's installed TypeScript compiler:

```sh
node scripts/generate-rust-contracts.mjs --write
node scripts/generate-rust-contracts.mjs --check
```

`--write` renders the selected declarations and their manifest. `--check` detects either file drifting without changing it. Named field references must resolve to an explicitly configured declaration. Same-module references use the compiler's exact declaration identity. Ordinary cross-module type references require a named type-only binding and an explicit `typeImports` entry proving the unique selected declaration. For packages, that proof includes the type entrypoint and complete one-hop re-export list. The manifest records all inputs to the proof. Only explicit `fieldProjections` can inspect an existing named value import within that graph, and only to prove a type query; they add no runtime imports. Arbitrary dependency graphs, unconfigured references, and reference cycles remain unsupported. Catalog-derived choices must come from one of the explicit local `as const` tuple forms below. Parentheses around a readonly array element retain the underlying supported type. A tagged object union requires an explicit discriminator in the config. Every member must declare that required readonly property with a distinct string literal or exact `null`.

The `ordered-finite-f64-record` field mapping opts into the exact `Readonly<Record<string, number>>` form. The compiler resolves both utilities to the pinned TypeScript standard-library declarations; other utility and generic shapes are unsupported. The generator records that library's digest in the manifest only when it uses the mapping. The generator does not execute modules. Do not edit generated files by hand.

The `base` option opts a root into a single bare `extends` clause whose target is an explicitly configured, exported interface in the same source. The generated fields stay flat, in base-then-own order. Inherited fields keep their declaring interface's metadata and nested Rust types; redeclaring them or mapping them again in the child is unsupported.

A `localInterface: true` root instead selects an unexported readonly interface solely as the configured same-source base of an exported interface. `wireFieldNames` can bind selected nested quoted numeric-range fields to portable Rust identifiers; the generator records the exact original wire name separately from the Rust spelling. Missing, unused, and colliding mappings are rejected.

For a root configured with both `base` and `discriminator`, only the exact `SameSourceConfiguredInterface & (InlineArm | ...)` alias form is supported. Each arm must have a string tag and reuses the base's fields in flat base-then-arm order, without redeclaration or a new wire tag. An arm-specific `const-string` field mapping uses the exact form `[wire_tag].field` and applies only to that one arm. Other mappings on tagged unions remain unsupported.

For an interface, `base` with `omitBaseFields` admits a single exact `extends Omit<ConfiguredInterface, ...>` clause. It proves the pinned utility, the configured base declaration (local or an approved type-only import), and the exact omitted field names. Non-omitted fields retain their original representations and order. The interface replaces exactly the omitted fields, in its own declaration order; it cannot redeclare a retained field.

The `catalog` option selects an additional literal enum source form. `satisfies-string-tuple` extracts the strings from a local `as const` tuple followed by a simple `satisfies readonly NamedType[]` clause; it does not evaluate or typecheck the constraint. `string-property` extracts one explicit string-valued property from each row of a local `as const` tuple of literal objects, matching the alias's indexed-access key. `unsigned-safe-integer-tuple` uses the exact `(typeof LOCAL_CONST)[number]` form and accepts only ordinary unsigned decimal safe-integer literal elements in a nonempty local `as const` tuple. All three check the local const declaration's identity and preserve catalog order. Duplicate entries and dynamic or ambiguous rows are unsupported.

The `finite-metric-record` and `empty-metric-record` field mappings accept only the pinned TypeScript `Readonly<Partial<Record<Metric, number>>>` and `Readonly<Partial<Record<Metric, never>>>` forms, respectively, with `Metric` bound to a configured local string enum. Order-preserving vector storage does not change the object's wire shape or enforce unique and finite entries. The `empty-json-array` and `exact-null` mappings preserve distinct literal markers. `const-string-property` reads a single `typeof LOCAL_CONST.member` from the exact local `as const` string object without running the module.

The `objectUnion` option names each Rust variant of a union of configured readonly interfaces. Public roots ordinarily require local arms; `importedObjectUnion: true` additionally permits an exact configured named type-only import of a readonly interface. Private roots follow the separate `localAlias` rules below. The generator checks each direct reference's exact declaration and emits variants in TypeScript source order. The enum reuses the original payloads. Variant names are Rust-only; they do not select a JSON tag or assert that all structurally possible inputs are unambiguous.

A `typeImports` row can also prove a direct named type-only sibling import. It matches an exact relative `./name.js` specifier to the explicitly configured sibling `name.ts`; it does not follow re-exports from that sibling.

The `literalUnion` option identifies one exact property projection from a named local union of inline readonly object arms. When the source alias is also configured as a root, it must be an exact public tagged union with an explicit discriminator; the generator tracks that dependency for cycle detection. The result combines the selected property's closed string and null values with the configured root's other direct string/null alternatives or proven string-enum references. Repeated values collapse in first source order. The `const-string` field mapping accepts a bare `typeof LOCAL_CONST` bound to an unannotated top-level local const with a direct quoted string initializer, optionally asserted `as const`. It does not evaluate expressions or accept a widened annotation or assertion. The `flat-interface-extension` mapping accepts one configured local readonly interface intersected with one literal readonly object, optionally wrapped by exact null. It preserves the flat field order and forbids redeclaration.

The `finite-partial-metric-record` mapping accepts the exact bare `Partial<Record<Metric, number>>` shape with a proven configured enum key. The explicit `fieldProjections` options bind a readonly const-catalog array or a single function's declared return type to an exact configured string enum. They examine only the existing type queries and declarations; they do not emit value imports, call functions, or infer their results. An explicitly selected `localAlias` must be an internal named union reachable from a public root. It may reuse proven imported payloads or a nested configured named union without adding wire tags. Imported loader aliases are allowed only when their configured two-state reason or maintenance extension rule has already proven the original payload shape.

The `unsigned-safe-integer-enum` field mapping admits a required field whose type is a direct numeric-literal union and applies the same canonical unsigned integer constraints as the root enum. The `exclude-literal` field projection accepts only the pinned TypeScript `Exclude<ConfiguredStringEnum, "one literal">` utility, with the enum proven by normal declaration identity. The excluded value must occur in that enum and leave a nonempty result. This preserves the original rendering order of the remaining wire values without admitting other conditional types.

The `frozen-const-string-property` mapping proves one string-valued `typeof LOCAL_CONST.member` from a local const initialized with a pinned builtin `Object.freeze({ ... } as const)` form. `frozen-const-string-property-union` does the same for exactly two distinct direct queries, in source order. These proofs inspect exact source syntax and compiler declaration identities; neither executes the initializer or accepts arbitrary calls.

The `indexed-literals` field projection follows only named declarations listed in the root's `indexedLiteralSources` map. It selects the same required readonly field from each closed object arm or a direct non-inheriting interface. A dotted projection path targets a nested field; a chained indexed access must select that same literal field. An intersection may add other fields but cannot redeclare the projected field. A pinned `Extract` of a configured string enum may narrow the field to an exact listed subset. Repeated literals collapse in source order, and null remains distinct from absence.

The `omit-interface-array` field projection admits only `readonly Omit<SameSourceConfiguredInterface, "one field">[]`. The compiler proves the configured readonly interface and the pinned utility. A generated flat entry reuses the original field metadata and order, minus one proven field; the output is a vector of that entry type, not a new serializer or a general mapped-type evaluator.

The root-level `pick` option accepts only a direct, pinned `Pick<ConfiguredInterface, "field" | ...>` selecting an exact ordered list of fields. The target must be a public, configured, non-inheriting readonly interface in the same source. The generated struct preserves the selection's order and copies complete field type and annotation blocks from the original Rust declarations. No field overrides or other root metadata may be combined with the selection.

The `readonly-inline-object-array` mapping accepts one required direct `readonly Readonly<{ ... }>[]` field. It proves the pinned utility on the explicit inline element, renders an ordered Rust vector, and applies readonly only to the direct element properties. An optional, nullable, aliased, mutable, or different array form is not accepted through this mapping.

The `interface-field` projection admits only a direct `ConfiguredLocalInterface["field"]` lookup of the identically named required readonly field, and reuses its exact generated Rust type. The `readonly-inline-object` mapping accepts only the pinned `Readonly` over a direct inline object of explicit properties. The wrapper supplies readonly only for its direct members, not nested objects. Outer optional presence and exact null remain independent. The `unsigned-safe-integer-literal` mapping preserves a required, canonical decimal integer as a zero-sized marker with an exact `u64` wire constant.

The `runtime-f64` mapping preserves a required direct `number` or exact `number | null` as `f64` or `Nullable<f64>` for internal runtime storage. Unlike `finite-f64`, it includes NaN and infinities and does not describe a JSON wire type. It does not admit optional fields, numeric aliases, or collections.

The `readonlyTaggedUnion: true` root option requires a discriminator and no base. Every arm must be a direct pinned TypeScript `Readonly<{ ... }>` of an inline object with a required exact string tag. Readonly applies only to the wrapper's own fields. Qualified paths such as `[forecast].attempt` use `utc-iso`, `safe-unsigned-integer`, or `unsigned-safe-integer-enum` for scalar fields. A direct arm field may itself be mapped with `readonly-inline-object`; paths one level inside it use only the scalar mappings and must explicitly name the same arm and wrapper. Unwrapped, mixed, null-tagged and deeper mapped forms are unsupported.

The `uint8array-bytes` mapping uses the pinned TypeScript standard-library identity of one bare `Uint8Array` field, with or without a single exact null alternative. It emits an owned Rust `Vec<u8>` or `Nullable<Vec<u8>>` without choosing a JSON encoding or copying the TypeScript array's buffer-view semantics into the contract. Optional fields retain ordinary `FieldPresence`, independently of null and empty bytes. Wider unions, type arguments, and other typed array identities are unsupported.

The `pgRowNamedFields` opt-in admits one exported nongeneric interface extending the exact type-only `pg.QueryResultRow` marker. The compiler follows only the pinned ESM declaration facade and target. The manifest records the installed marker inputs. The marker contributes only an open index signature, so the projection contains the declared named fields, not arbitrary PostgreSQL columns.

The root-level `readonlyNullableMetricRecord` option accepts only an exported alias of the pinned `Readonly<Record<Key, number | null>>` utilities over the exact configured string-enum root. Each catalog key must be a portable field name, and the generated struct requires every key in catalog order with a `Nullable<f64>` value. There is no `Partial` or omitted-key form.

The root-level `disabledReasonExtract` option is limited to direct two-arm loader `state` unions. Both arms require readonly `bundle`, `reasonCode`, and `state` fields; only the active arm can also declare an optional readonly `comparatorAuthority`. The active bundle is a named type reference and its reason stays null. The disabled bundle stays null and its reason must use the pinned `Extract<ConfiguredEnum, ...>` with distinct direct string literals from that exact configured enum. Rust keeps the source subset order and distinguishes it from the full reason enum.

The `frozen-const-literal-object` mapping accepts a required readonly interface field declared as `typeof LOCAL_CONST`. The same-module top-level const must use the pinned builtin `Object.freeze({ ... } as const)` with a nonempty set of uniquely named direct string or canonical unsigned safe-integer literal properties. Rust retains each field and its literal marker in declaration order without running the initializer.

The `frozen-wind-metric-band-tuple` mapping accepts a required readonly interface field declared as `typeof LOCAL_CONST`. The local const must wrap a nonempty `as const` array of direct string-literal `leadBand` and `metric` properties in that order. A dedicated `tupleIdentityWrapper` sibling edge proves the existing named value binding and its explicit `<T>(value: T): T` signature; it does not add a runtime import. The generated marker exposes the original keys and fixed sequence without storing a list per registry value.

The `maintenanceLoaderExtension` rule selects one original three-arm alias. Its legacy arm intersects a configured two-state result with a single optional comparator; it cannot redeclare a property on that result. The required comparator and the exact active null or disabled `policy_raw` reason remain in the maintenance arms. The active bundle's selected `candidate` or `model` field must index the identically named direct readonly field of the configured imported package interface. These are data declarations only, not serialization or loader execution rules.

The `activeImportedConstString` option selects one required readonly field in an `active`/`disabled` state union. The active field must use `typeof` on the exact named import, and the disabled field is exactly null. A dedicated `literalStringValue` sibling edge is consumed only for an explicit, unannotated exported const with a quoted string initializer. The generator parses its declaration without evaluating or importing runtime code.

The `numeric-pair-template` mapping requires a direct, required, readonly field of type `` `${number}-${number}` ``. It stores the value as a Rust `String`; the generated type does not enforce the template or validate a calendar month at runtime. The `float32array-values` mapping requires a direct, required `Float32Array` bound to the pinned compiler library. It stores ordered values as `Vec<f32>` without filtering out non-finite values or signed zero. It does not model JSON representation, buffer identity, byte offsets, or aliasing.

The `direct-const-string-tuple` catalog opt-in accepts `typeof LOCAL_CONST[number]` from one same-module `as const` tuple of direct string literals. The existing parenthesized catalog syntax is unchanged. The `runtime-f64-array` mapping keeps a required direct `readonly number[]` as an ordered `Vec<f64>` without restricting non-finite values.

The `rain-hurdle-head-record` mapping proves the pinned `Readonly<Record<...>>` wrappers, exact four key strings, and the private same-module head and tree declarations. It exposes the ordered source keys in `WIRE_KEYS` and keeps each tree as `[Vec<f64>; 5]` without requiring equal vector lengths or validating the model. The v2 artifact uses `addedAfterOmit` to name the original `projectionId` field after replacing `contractVersion`; other `Omit` roots still allow only their configured replacements by default. No parser, serializer, model selection, or tree traversal is generated.

The `identicalImportedStringFields` option requires an already proven `importedBase`. Each listed field must be a direct, required, readonly primitive `string` in both source interfaces with no representation mapping. The inherited Rust `String` field stays in its original position, and only the matching duplicate declaration is skipped. Unlisted, optional, changed, or mapped duplicates remain unsupported.

The `pgQueryOwners` option keeps a `pgRowNamedFields` interface private in TypeScript while selecting its named data fields for Rust. Each configured exported async function must contain one direct awaited `Pool.query<Row>` call with a literal `SELECT` and explicit bindings, and no other direct query may select the same row. The compiler proves the private row, owner, and pinned `Pool` call identities. A narrow parser checks the declared output names and numbered binding slots against the interface and argument list. It does not interpret the rest of the SQL, validate PostgreSQL types, or execute a query.

The `grouped-unsigned-safe-integer-literal` mapping accepts one required direct numeric literal grouped by thousands, such as `2_000`, and exposes its exact unsigned value without storing an integer in each instance. `unsigned-decimal-enum` accepts a required direct union of distinct canonical nonnegative decimal literals in the safe integer magnitude range, including at least one fractional value. It preserves TypeScript order and emits an exact binary64 value table. Ordinary integer literals and unions still use their existing mappings.

Use `ownFieldOrderAfterOmit` when a TypeScript extension places new fields before or between the fields it replaces. This option must name the complete ordered list of own fields, including every omitted field's replacement and at least one new field. It cannot be combined with `addedAfterOmit`. Retained inherited fields keep their original order; only then are the checked own fields emitted in declaration order.

The `readonly-unsigned-counter-record` mapping verifies a required direct `Readonly<Record<Key, number>>` using the pinned TypeScript utilities and a configured local string-literal key type. A single literal is allowed. It preserves the declared key order and uses safe unsigned integer storage for producer counts. It does not implement count validation, default values, or serialization.

The `js-date` mapping accepts a required, direct pinned `Date` and emits only its time value or an explicit invalid variant. It does not add a text or null alternative or perform UTC normalization.

The `js-date-or-string` mapping requires the pinned builtin Date identity and direct primitive string in a required field, with at most one explicit null arm. The shared enum keeps the Date time value (including an explicit invalid case) distinct from unparsed string code units. It does not model JavaScript Date identity or methods and is not an API wire type.

The `runtime-f64-nullable-array` mapping accepts a required `readonly (number | null)[]`; `ordered-runtime-f64-nullable-array-record` accepts that same array as the value of a pinned `Readonly<Record<string, ...>>`. Either payload may have an explicit outer null. The vectors keep ordered binary64 samples and null slots, and the ordered record stores UTF-16 key units. These mappings express storage only and do not parse or serialize JSON.

A `proofExports` binding proves a declaration for an indexed projection without making it a generated or ordinarily importable root. For the database package's compiled entry, `compiledSource` pins the existing package metadata and TypeScript configs, verifies the declared source-to-output path, and uses the complete original source barrel. The generator neither reads `dist` nor builds the package.

The `ordered-json-scalar-object` mapping accepts one required, pinned `Readonly<Record<string, string | number | boolean | null>>` with exactly those four direct alternatives. It stores ordered key/value pairs with UTF-16 keys and strings and a scalar value enum that cannot hold nested objects or arrays. Finite numbers and unique keys remain validation rules, not guarantees of vector or floating-point storage.

The `ordered-json-key-object` and `ordered-json-nullable-string-object` mappings use the same pinned record proof but require exactly `string | number | null` or `string | null`, respectively. The `ordered-json-scalar-object-array` mapping requires a direct readonly array of the four-alternative scalar record. The generated vectors preserve both row order and entry order; these mappings do not perform JSON serialization or key validation.

The `readonly-string-literal-record` mapping accepts only a required, pinned `Readonly<Record<"field" | ..., string>>` with distinct direct string-literal keys that are portable Rust field identifiers. It emits one struct with those required string fields in source order. It does not accept a widened key type or decide how the strings are validated or encoded.

The `const-scalar-property` mapping selects one exact `typeof LOCAL_CONST.member` from a same-module `as const` object. Every member must be a uniquely named ordinary property with a direct string or finite decimal literal value. Numeric markers use `f64::from_bits`; no object initializer runs. The `extend-local-string-enum` catalog accepts one exact configured same-module direct string enum reference followed by one new string literal, in that order. It does not change the original enum or accept indirect references.

The `importedBase: true` option allows direct inheritance from one exact configured public interface via a named type-only import. Ordinary inheritance remains same-source without the opt-in. On an exact `Omit` base, `omitInheritedBaseFields` explicitly lists which omitted-and-replaced fields must come from the rendered base's inheritance rather than its own declaration.

The `indexed-interface-field-extension` projection accepts one direct imported configured interface's required readonly inline object selected by the same literal field name. It copies the original generated field blocks and appends one new explicit required readonly field. This describes Rust field order, not JSON serialization order.

The `defaultedListParameter` option selects exactly one unconstrained type parameter on an ordinary readonly interface, with an exact configured type-only imported default and one explicitly selected required readonly array of that parameter. It emits the corresponding Rust type parameter and default, and does not allow generic input references elsewhere in the generator.

The `recursiveJson` root option names the local primitive alias and admits only the readonly recursive JSON grammar proven against that root's declaration. Its two recursive edges use vector storage, giving a sized Rust enum without accepting arbitrary reference cycles. The `ordered-json-object` field mapping admits a pinned `Readonly<Record<string, ...>>` of that exact configured JSON root, optionally under exact null. It stores entries as ordered pairs and does not change the wire object into an array. These are type declarations only; no canonical bytes, text encoding, serializer, or wire parity are inferred. Ordinary, non-JSON string fields retain the generator's existing Rust `String` mapping.

Runtime imports, serialization, wire parity, build/CI integration, and the benchmark remain behind the migration's existing gates.
